# 提出指標 - 步驟規則內聚性

為了解決 `specs/003-步驟規則內聚性/問題定義.md` 之問題，
提出 skill mutation 必須要針對 `步驟規則內聚性` 指標去最佳化。

## 描述

**步驟規則內聚性（Step-Rule Cohesion）** 衡量一個 step 透過 `adhere` 載入的規則，有多少比例直接約束該 step 的當下職責，而不是提供全域背景、前序判斷或保險式提醒。

此指標的核心判準：

> 一條 `adhere(s, r)` 若被移除，`s` 是否會因此更容易產生錯誤 artifact、錯誤判斷或錯誤執行方式？

若答案是「會」，該 edge 內聚性高。若答案是「不會，只是整體上知道比較好」，該 edge 內聚性低。

本性質不是檢查 ref 是否存在；ref closure 已由 HES I₁ 保證。本性質檢查的是 **ref 是否貼在正確 step 上**。

## 指標

### 1. Edge Relevance（單條 adhere 的語意相關性）

對每條 `adhere(s, r)`，將 RuleFile `r` 拆成 AtomicRule 集合：

```text
A(r) = {a1, a2, ..., an}
```

對每條 AtomicRule `a` 計算其對 step `s` 的 relevance：

| 分數 | 定義 |
|---|---|
| `1.0` | 直接必要。不載入此 rule，step 高機率會做錯。 |
| `0.7` | 局部輔助。rule 影響 step 邊界或品質，但不是主約束。 |
| `0.3` | 背景相關。理解它有幫助，但 step 不依賴它完成。 |
| `0.0` | 無關、重複或前序已決定。 |

```text
EdgeRelevance(s, r) = average(relevance(a, s) for a in A(r))
```

門檻：

| 分數 | 判定 |
|---|---|
| `>= 0.80` | 高內聚 adhere。保留。 |
| `0.50–0.79` | 可疑。考慮 split RuleFile 或改掛更窄 rule。 |
| `< 0.50` | 低內聚 adhere。應移除、改掛或重構。 |

### 2. Step Focus（單一 step 的注意力純度）

衡量一個 step 載入的所有 AtomicRule 中，有多少真正服務該 step。

```text
LoadedAtoms(s) = union(A(r) for r in s.adhere)
RelevantAtoms(s) = { a in LoadedAtoms(s) | relevance(a, s) >= 0.7 }
StepFocus(s) = |RelevantAtoms(s)| / |LoadedAtoms(s)|
```

若 `s.adhere = []`，且 step 不需要外部 rule，`StepFocus(s) = 1.0`。

門檻：

| 分數 | 判定 |
|---|---|
| `>= 0.75` | 注意力集中。 |
| `0.50–0.74` | 有 noise，需審查。 |
| `< 0.50` | 規則污染；step 載入太多非局部約束。 |

### 3. Rule Fanout Purity（RuleFile 被多 step 使用時的 concern 純度）

同一 RuleFile 被多 step adhere 不一定錯。錯的是同一 RuleFile 跨越多種 step concern 被廣播。

定義：

```text
Adherers(r) = { s | r in s.adhere }
Concern(s) = semantic concern of s
RuleFanoutPurity(r) = max_count_same_concern(Adherers(r)) / |Adherers(r)|
```

`Concern(s)` 可由 `verb + text + flow position` 判斷，例如：

- `classify-family`
- `write-test`
- `write-stub`
- `verify-red`
- `route-to-variant`
- `report-result`

門檻：

| 條件 | 判定 |
|---|---|
| `|Adherers(r)| <= 2` | fanout 小，通常不處理。 |
| `|Adherers(r)| >= 3` 且 `RuleFanoutPurity(r) >= 0.70` | 可接受復用。 |
| `|Adherers(r)| >= 3` 且 `RuleFanoutPurity(r) < 0.70` | broadcast smell。 |
| `|Adherers(r)| >= 5` 且跨 `think/write/run` | 高風險 rule 污染。 |

### 4. Cohesion Score（總分）

對整個 genome `G`：

```text
EdgeScore(G) = average(EdgeRelevance(s, r) for every adhere(s, r))
StepScore(G) = average(StepFocus(s) for every Step s)
FanoutScore(G) = average(RuleFanoutPurity(r) for every RuleFile r with |Adherers(r)| >= 3)

StepRuleCohesion(G) = 0.50 * EdgeScore(G)
                    + 0.35 * StepScore(G)
                    + 0.15 * FanoutScore(G)
```

權重理由：

- Edge 精準度最重要，因為 mutation 真正改的是 `adhere` edge。
- Step focus 反映執行時 context load。
- Fanout purity 是 smell detector，不應壓過 edge / step 的局部判斷。

### 5. Gate / Reward 建議

| 條件 | 處理 |
|---|---|
| `EdgeRelevance(s, r) < 0.50` | Veto 該 `adhere` edge，除非有明確例外註記。 |
| `StepFocus(s) < 0.50` | Veto 該 step 結構，需拆 rule 或移除不相關 adhere。 |
| `RuleFanoutPurity(r) < 0.70` 且 fanout >= 3 | Weighted penalty；提示 hoist/sink/split rule。 |
| `StepRuleCohesion(G) >= 0.80` | 可接受。 |
| `StepRuleCohesion(G) < 0.70` | 不建議 accept mutation。 |

### 6. 評估型別

可自動化部分：

- `|s.adhere|`
- `|Adherers(r)|`
- RuleFile fanout
- 是否同一 RuleFile 跨多 verb 類型（`think/write/run/delegate/read`）
- 是否某 step 載入過大的 RuleFile（AtomicRule count 過高）

需 LLM / human judge 部分：

- AtomicRule 對 step 的 `relevance(a, s)`
- `Concern(s)` 分類
- 前序決策是否已經消化該 rule，不應在後續 step 重新 adhere

### 7. GOOD / BAD 校準

GOOD：

```json
{
  "step": "tdd-red#s2",
  "text": "依分類規則判斷當前應走哪個 packaged variant。",
  "adhere": ["./rules/test-family-routing.md"]
}
```

原因：step 主職責就是 family classification；RuleFile 直接約束當下判斷。

BAD：

```json
{
  "step": "tdd-red/variants/tdd-red-code-level-ut#s4",
  "text": "production code 僅含 stub 或樣板（不得實作該行為）。",
  "adhere": [
    "tdd-red::rules/production-stub.md",
    "tdd-red::rules/test-family-routing.md"
  ]
}
```

原因：此 step 主職責是 production stub；它需要 `production-stub.md`，不應重新載入整份 family routing。family 應在前序 routing / variant dispatch 已決定。

### 8. 與 mutator 的關係

優化此指標時，常見修法：

- `w` REWIRE-REF：把 step adhere 改到更窄 RuleFile。
- `xr` EXTRACT-RULE：從大 RuleFile 中抽出該 step 真正需要的小規則檔。
- `ir` INLINE-RULE：只有單一步驟使用的小規則可內聯回 step。
- `h / sk` HOIST-SINK：調整共享 rule 的位置，但不得把共享誤當 broadcast。
- `ps / pm` SPLIT-MERGE-STEP：若 step 本身混合多 concern，先拆 step 再貼 rule。
