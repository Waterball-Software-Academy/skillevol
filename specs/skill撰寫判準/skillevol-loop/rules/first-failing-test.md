# 先跑單條測試規則

本檔只規範如何選定並執行第一條測試，以及如何判斷它是否真的抓到目前問題。

## Rule 1 — 新測試必須先證明會抓到目前問題

- 新增、修改或採用的測試必須先對目前 skill 執行。
- 合理結果是測試失敗，且失敗內容對應使用者要修的問題。
- 若測試一開始就通過，必須判斷是目前 skill 已經滿足需求，還是測試太弱；不能拿弱測試當修改依據。
- 這個「先確認測試會失敗」的檢查，在本流程中可稱為 `red gate`。

### Good

情境: 新增「產出計畫後不得直接施工」測試後，現有 skill 仍直接施工。

```
測試結果: fail
失敗原因: 互動順序錯，產出計畫後沒有停下來問使用者
```

結果: 新測試真的能抓到使用者在意的缺陷。

### Bad

情境: 新測試沒跑就開始修改。

```
測試看起來已經寫好，我直接重構 SKILL.md。
```

結果: 不知道這條測試是否有效，loop 可能對錯誤目標優化。

預期改法:

- 先委派 `/skillevol-run-eval` 跑該測試；若沒有合理失敗，回到缺口分析或修測試。
