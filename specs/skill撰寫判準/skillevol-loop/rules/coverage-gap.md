# 驗證缺口分析規則

本檔只規範如何判斷現有驗證是否覆蓋使用者想修的問題，以及如何用白話說明缺口。

## Rule 1 — 補測試前必須先用白話說明缺口

- 當使用者想修的問題沒有被現有測試覆蓋時，必須先說清楚現有測試已測什麼、沒測什麼、因此漏抓什麼行為。
- 這段說明要讓使用者不用懂 `oracle`、`adequacy`、`provenance` 也能判斷方向對不對。
- 說明結尾只能提出一個清楚的補測試方向：擴充既有測試，或新增一條測試。

### Good

情境: 使用者要求某 plan skill 寫完計畫後先等確認，但現有測試只看有沒有產出計畫。

```
現有測試只看它有沒有寫出計畫，沒有看它寫完後是直接開始施工，還是停下來問你要不要開始。
所以現在就算它跳過確認，這組測試也抓不到。
這次應新增一條測試，專門驗「產出計畫後不得直接施工」。
```

結果: 使用者能判斷補測試方向是否對齊自己在意的問題。

### Bad

情境: 同一需求。

```
目前 eval adequacy 不足，需補 oracle 並觀察 provenance。
```

結果: 句子像內部標籤，使用者不知道到底缺哪條測試。

預期改法:

- 改成白話描述：現有測了什麼、沒測什麼、漏抓什麼，最後只提出一個補測試方向。
