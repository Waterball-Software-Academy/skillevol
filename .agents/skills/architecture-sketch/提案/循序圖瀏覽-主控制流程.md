# 提案：循序圖瀏覽（主控制流程 sequence diagram）

> 狀態：提案，待 confirm。confirm 前不修改 `架構互動.html`。
> 對象：`specs/truth/architecture/架構互動.html`（ELK 互動架構圖）。

## 1. 概念

- 現在的圖是**結構視角**：模組／類別／依賴／邊界（space）。
- 它回答「誰依賴誰、邊界在哪」。
- 它**回答不了**「一次演化**按什麼順序**發生、誰先呼叫誰、retry／gate 怎麼分支」（time）。
- 循序圖（UML sequence）正是這個**時間視角**的補件。
- 兩者共用同一份控制流模型 → 結構圖上的 `①②③④` 與循序圖**永遠一致**。

## 2. 為什麼現在畫不出循序圖（核心問題）

- 目前跨模組邊只有 `{from, to, label, kind, seq}`，太粗。
- 循序圖需要：**訊息順序、簽章、引數、回傳值、activation（同步）、巢狀子呼叫、控制片段（loop／alt／opt）、lifeline 參與者**。
- 例：`runTurn` 的「被拒重試 ≤ 10」是 **loop**、`gate` 的 auto／rejected 是 **alt**、`applyMutation` 內部六關卡是**巢狀子呼叫**——這些現在的資料完全沒有。
- 所以要做 **data refining**：新增一份比 edges 更細的「互動腳本」模型。

## 3. 規格

### 3.1 新資料模型：`FLOW`（互動腳本，SSOT）

参與者（lifelines，左→右排序）：
```js
PARTICIPANTS = [
  {id:'user',     label:'使用者',          kind:'actor'},
  {id:'chat',     label:'ChatPanel',       mod:'chat'},
  {id:'reg',      label:'MutatorRegistry', mod:'mut'},
  {id:'run',      label:'runTurn',         mod:'orch'},
  {id:'sdk',      label:'SdkPort',         mod:'orch'},
  {id:'apply',    label:'applyMutation',   mod:'eng'},
  {id:'mut',      label:'«Mutator»',       mod:'eng→mut'},
  {id:'gates',    label:'schema/wf/canonical', mod:'eng'},
  {id:'sess',     label:'EvolutionSession',mod:'eng'},
];
```

訊息腳本（巢狀＋控制片段）：
```js
FLOW = [
  {from:'user', to:'chat', msg:'輸入演化意圖'},
  {from:'chat', to:'reg',  msg:'getMutators()', ret:'Record<name,Mutator>', kind:'wire'},   // ⓪
  {from:'chat', to:'run',  msg:'runTurn(g, intent, port, mutators)', activate:true, seq:1, children:[
    {frag:'loop', label:'retry ≤ MAX_RETRIES(10)，被拒則重組 rejectionNote 再試', children:[
      {from:'run', to:'sdk', msg:'complete(system, user, tools)', ret:'AssistantMsg(tool_uses)'},
      {frag:'loop', label:'每個 tool_use', children:[
        {from:'run', to:'apply', msg:'applyMutation(G, call, mutators)', seq:2, children:[
          {from:'apply', to:'mut',   msg:'apply(G, args)', ret:'G′'},
          {from:'apply', to:'gates', msg:'validateSchema → wf → versionId', seq:3, ret:'ok / 違例'},
        ], ret:'Result{ gate, G′ }'},
        {frag:'alt', label:'gate', branches:[
          {cond:'auto',     children:[{from:'run', to:'run', msg:'current = G′（接受）'}]},
          {cond:'rejected', children:[{from:'run', to:'run', msg:'break；附 rejectionNote'}]},
        ]},
      ]},
    ]},
    {from:'run', to:'chat', msg:'TurnOutcome{ genome, messages }', kind:'return'},
  ]},
  {from:'chat', to:'sess', msg:'onCommit → commit(G′)（落版本鏈）', seq:4},
];
```

### 3.2 規則（讓主控制流程「畫得出循序圖」）
1. 每步必須指名：caller、callee（**具體類別/函式 lifeline，不是模組**）、訊息簽章。
2. 有意義的**回傳值**要寫（`Result`、`TurnOutcome`、`AssistantMsg`）。
3. **控制片段**要標：`loop`（retry、每個 tool_use）、`alt`（gate auto/rejected）、`opt`。
4. participants = 主路徑上實際出現的 lifelines（全類別的子集），依首次出現排序。
5. `FLOW` 是 SSOT：同時驅動「結構圖的 `①②③④` 徽章」與「循序圖」→ 兩視圖一致。

### 3.4 雙向同步高亮的連結鍵（v1 內含）
- 結構圖 edge 與循序圖 message 以**共用 `seq` 鍵**綁定（`①②③④`）。實作：兩邊 DOM／SVG 元素掛 `data-seq`。
- hover 任一邊的 `seq` 元素 → 兩邊對應元素同時高亮（加粗／提亮），其餘**降透明**聚焦。
- click 結構圖 `①` → 右側循序圖**捲動**到該 message。
- 無 `seq` 的 message（如 `getMutators` wire、return）只在循序圖內 hover 高亮，不跨圖（無結構對應）。

### 3.3 循序圖怎麼渲染：**手刻原生 SVG**（已定）

- 不用 Mermaid／任何第三方——第三方 HCI 差、皮膚不一致、受限。自繪掌控全部。
- 自寫小型循序圖佈局器，從 `FLOW` 直接算座標、吐 SVG：
  - **lifeline**：participant header（模組色點＋函式名）＋往下的 dashed 垂直線。
  - **message**：caller→callee 水平箭頭＋label；self-message 小迴圈；return 用 dashed 反向箭頭。
  - **activation bar**：被呼叫者 lifeline 上一條細 rect，從進入到其子呼叫結束。
  - **fragment**：`loop`／`alt` 畫外框＋左上角標籤 tab；`alt` 分支間 dashed 分隔線＋ cond 標。
  - **序號**：帶 `seq` 的 message 畫 ①②③④ 圈在箭頭起點。
- 皮膚沿用本圖：mono 字、warm paper、edge 配色（call 墨／wire 藍／realize 綠／smell 紅／return 灰虛）。
- 代價：自寫佈局（activation／巢狀／fragment 框）約一支函式的工。換來完全一致皮膚 + 零新 CDN（離線只剩既有 elkjs 依賴）。

## 4. UI / UX

### 4.1 互動
1. 頂部工具列加一顆 **toggle 按鈕「循序圖」**。
2. ON → 舞台**左右分割**：左＝結構互動圖（變窄），右＝循序圖面板（可捲動），中間可拖曳分隔線。
3. OFF → 結構圖回到全寬（現狀）。
4. 右面板標題：`主控制流程 · 一次演化`。
5. **雙向同步高亮（v1 內含）**：hover 左圖 `①②③④` ↔ 右圖對應 message 同時高亮、其餘降透明；click 左圖序號捲動右圖到該訊息。詳見 §3.4。

## 5. 已定方向（render 經第二輪定案）
- 渲染：**手刻原生 SVG**（不用 Mermaid／第三方）。
- 版面：**左右分割 + 可拖曳分隔線**（非彈窗）。
- lifeline 顆粒度：**函式級**（runTurn／applyMutation／wf…），貼控制流。
- `«Mutator»`：畫成**介面 lifeline**（apply 動態分派到具象，靜態看是呼叫抽象）。
- `FLOW` = 控制流 SSOT；結構圖 `①②③④` 與循序圖同源。
- FLOW 範圍：**happy path + retry loop + gate alt**（不含錯誤旁支）。
- **雙向同步高亮：v1 內含**（hover 互亮 + click 捲動，見 §3.4）。

## 6. 殘留／後手
- 若日後要離線：elkjs 已是唯一外部依賴，循序圖自繪不再增 CDN。
- 錯誤旁支（throw／rollback 細節）暫不入循序圖，需要再補 `alt`。
